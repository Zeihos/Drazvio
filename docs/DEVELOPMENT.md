# Разработка и техническая часть

## Технологии

- **Pawn 3.2.3664** — основной `server/gamemodes/mod05.pwn` и фильтрскрипты.
- **C++ / Win32** — экспериментальный совместимый плагин FileFunctions.
- **SA-MP 0.3.7-R2** — среда выполнения.
- **PowerShell + Python 3** — автоматизация и проверки.
- **GitHub Actions** — компиляция и тестирование.

## Основные команды

```powershell
# Проверить исходники и зависимости
python tools/drazvio.py check

# Проверить, что в Git не попали секреты/архивы
python tools/repository_audit.py

# Собрать Pawn без изменения файлов работающего сервера
./tools/build.ps1

# Создать локальную конфигурацию (не перезапишет существующую)
python tools/drazvio.py init
```

Опция `./tools/build.ps1 -Install` заменяет локальные `.amx` после сборки, предварительно сохраняя старые файлы рядом с ними. Используйте её **только после резервного копирования и проверки**, а не на работающем сервере.

## Автоматические проверки

| Workflow | Что проверяет |
| --- | --- |
| [Pawn build](../.github/workflows/pawn-build.yml) | Структура проекта, чистота Git и компиляция `mod05`, `gatesys2`, `reklama` |
| [FileFunctions compatibility](../.github/workflows/filefunctions-compat.yml) | Сборка 32-битной DLL, файловые тесты, запуск SA-MP с тестовым и полным режимами, формирование тестового ZIP |
| [Документация](../.github/workflows/docs.yml) | Наличие локальных ссылок и иллюстраций в Markdown |

Успешная проверка запуска **не равна** полноценному игровому тестированию: она подтверждает загрузку сервера и зависимостей в тестовом окружении.

## Почему не хранится готовый `mod05.amx`?

Бинарники из предыдущих этапов могли не соответствовать последнему исходнику. Сейчас генерируемые AMX собираются в CI и размещаются как артефакты. В каталоге фильтрскриптов сохранены сторонние AMX, для которых пока нет подтверждённой собственной сборки.

## Изоляция игровых данных

Игровые аккаунты, временные файлы сохранения, личный конфиг и резервные копии должны оставаться только на сервере. Для первичного запуска используются шаблоны `*.ini.example`; данные существующего сервера нельзя автоматически затирать.

## Внесение изменений

Перед отправкой PR проверьте исходники, добавьте воспроизводимый сценарий тестирования и укажите, какие игровые данные затрагиваются. См. [CONTRIBUTING](../CONTRIBUTING.md).
